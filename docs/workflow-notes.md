# Working notes

## Why tier, not one-size

A single cloud model for everything is simple and wrong. Simple tasks pay a latency + cost
premium and return nothing better; hard tasks get a plausible-but-shallow answer from a cheap
model. The fix is a router that knows what the task needs — not a bigger model.

## The verification rule

An agent that *looks* done and an agent that *is* done are different things. Two sources before
a firm claim. Read back the written file. Check the live process. "Done" is a state you confirm,
not a sentence you say.

## Cost is part of correctness

A solution that's expensive is not "better"—it's just expensive. The most useful number is
*cheapest solution that verifiably works*, not *most impressive one*.
